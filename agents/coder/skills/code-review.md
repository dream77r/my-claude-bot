# Skill: Code Review

**Принцип.** Ревью — это поиск контрпримера к коду: для каждой строки спроси «при каком входе / порядке / окружении это ломается?». Находка без воспроизводимого вреда — стиль; вред без предложенного фикса — нытьё. Ранжируй по `impact = P(срабатывания) × радиус взрыва`, не по объёму текста.

## Когда активировать
- «сделай ревью / review этого PR / проверь дифф перед мерджем»
- прислали ветку, MR, `.diff`/`.patch`, или «глянь, норм код?»
- перед `git merge` / `land` — последний рубеж до main
- просят оценить качество, читаемость, безопасность изменения
- **Не** активировать на «напиши код с нуля» (это authoring, не review) — но активировать, если код уже написан и спрашивают «ок?».

## Таксономия серьёзности

Каждая находка ОБЯЗАНА иметь ровно один severity. Метка определяет, блокирует ли она мердж.

| Severity | Определение | Блокирует мердж? | Примеры |
|----------|-------------|------------------|---------|
| **critical** | Эксплуатируемая дыра, потеря/порча данных, падение прода, утечка секретов. Срабатывает на реалистичном входе. | ДА — стоп до фикса | SQL injection, secret в коде, auth bypass, `DELETE` без `WHERE`, дедлок на горячем пути |
| **high** | Логическая ошибка на распространённом пути, гонка, сломанный контракт API, отсутствие обработки ошибки с реальными последствиями. | ДА (или явный follow-up тикет) | off-by-one в пагинации, N+1 на списочном эндпоинте, проглоченное исключение, breaking change без версии |
| **medium** | Корректно в типичном случае, ломается на грани; недостающий тест; снижение поддерживаемости. | НЕТ — чинить в этом же PR желательно | необработанный пустой список, флаки-тест, magic number, дублирование логики |
| **nit** | Косметика: именование, форматирование, мелкий рефактор. Вкусовщина — помечай как `nit:` явно. | НЕТ — автор решает сам | `i` → `index`, лишний комментарий, порядок импортов |

Правило эскалации: **если сомневаешься между двумя уровнями — бери выше и снижай аргументом, а не наоборот.** Critical/high требуют объяснения «как именно ломается», nit — нет.

## Чеклист по измерениям

Проходи КАЖДУЮ изменённую функцию по всем строкам. Колонка «триггер» — что искать грепом/глазами.

| Измерение | Что проверять | Триггер в дифе | Типичный severity |
|-----------|---------------|----------------|-------------------|
| **Корректность / логика** | граничные значения (0, -1, пусто, max), off-by-one, инверсия условий, ранний `return`, потерянный `await` | `<= vs <`, `and/or`, `range(`, `[i+1]` | high |
| **Безопасность: injection** | конкатенация в SQL/shell/HTML/LDAP вместо параметров | f-string/`+` рядом с `execute(`, `os.system`, `subprocess(... shell=True)` | critical |
| **Безопасность: authn ≠ authz** | проверка «кто ты» есть, но нет «можно ли тебе ЭТОТ объект» (IDOR) | `get(id)` без `where owner == current_user` | critical |
| **Безопасность: secrets** | ключи/пароли/токены в коде, логах, конфиге под git | `sk-`, `AKIA`, `password=`, `token =`, `BEGIN PRIVATE KEY` | critical |
| **Безопасность: SSRF** | запрос по URL из ввода без allowlist хостов/схем | `requests.get(user_url)`, `fetch(`, `urlopen(` | critical |
| **Безопасность: десериализация** | `pickle.loads`, `yaml.load` (не safe_load), `eval`/`exec` на недоверенном | `pickle`, `yaml.load(`, `eval(`, `marshal` | critical |
| **Безопасность: path traversal** | путь из ввода без нормализации/проверки префикса | `open(base + name)`, `../`, `os.path.join(user_input)` | critical |
| **Конкурентность / гонки** | check-then-act без атомарности, общий мутабельный стейт без лока, не-реентрантность, TOCTOU | `if not exists: create`, глобал `+=`, `await` между read и write | high/critical |
| **Обработка ошибок / грани** | голый `except:`, проглоченное исключение, нет таймаута на I/O, не закрытый ресурс, частичный коммит | `except: pass`, `except Exception`, нет `with`/`finally` | high |
| **Производительность** | N+1 запрос, O(n²) в цикле, блокирующий I/O в async, лишние аллокации/копии в горячем цикле | запрос внутри `for`, `requests` в `async def`, `time.sleep` в корутине | high/medium |
| **Контракт API / совместимость** | удаление/переименование поля, смена типа ответа, сужение принимаемого, новый required-параметр без дефолта | изменён публичный сигнатур/схема/JSON | high |
| **Тесты** | нет теста на новый код, только happy-path (нет негативных кейсов), флаки (sleep/время/порядок), assert без значения | новый код без `test_`, нет `pytest.raises`, `time.sleep` в тесте | medium/high |
| **Читаемость / именование** | имя врёт о содержимом, функция >50 строк / >3 уровней вложенности, мёртвый код, дублирование | длинные функции, закомментированный код, copy-paste блоки | nit/medium |

### Микро-формулы для ранжирования
- `impact ≈ P(срабатывания на реальном трафике) × (затронутые пользователи или строки данных)`. Critical ≈ высокая P и большой радиус; nit ≈ нулевой радиус.
- **N+1 цена:** `запросов = 1 + N`, где N = размер коллекции. На списке из 200 → 201 запрос вместо 2 (`JOIN`/`prefetch`). Флаг при N, растущем с данными.
- **Сложность цикла:** вложенный цикл по тем же данным = `O(n²)`. На n=10⁴ это 10⁸ операций — сотни мс в Python. Замена на set/dict-lookup → `O(n)`.
- **Async-блокировка:** один `time.sleep(1)`/синхронный `requests` в корутине блокирует ВЕСЬ event loop → деградация всех конкурентных запросов, не одного.

## Как применять (алгоритм)

1. **Определи базу.** `git merge-base HEAD origin/main` или спроси базовую ветку. Не ревьюй рабочее дерево «вообще» — ревьюй ИЗМЕНЕНИЕ.
   ```bash
   BASE=$(git merge-base HEAD origin/main)
   git diff --stat $BASE...HEAD          # масштаб: файлы и ±строки
   git diff $BASE...HEAD                 # сам дифф
   git diff --name-only $BASE...HEAD     # список тронутых файлов
   ```
2. **Прочитай тронутые файлы ЦЕЛИКОМ** (`Read`), не только дифф-хунки. Контекст вокруг строки решает, баг это или нет: вызывающий код, инварианты, существующие проверки выше по стеку.
3. **Пройди чеклист построчно** по каждому изменённому блоку. Для каждого подозрения сформулируй конкретный вход, который ломает код. Нет контрпримера → не критикуй как баг (максимум nit).
4. **Классифицируй** каждую находку по таксономии. Для critical/high сразу набросай фикс.
5. **Ранжируй** по `impact`: сначала всё critical, потом high, потом medium, в конце nit. Внутри уровня — по радиусу взрыва.
6. **Проверь тесты:** есть ли тест на новый путь? Покрыт ли негативный кейс (ошибка, пустой ввод, отказ прав)? Нет — это находка уровня medium/high.
7. **Вынеси вердикт:** `APPROVE` (нет critical/high) / `APPROVE с правками` (только nit/medium) / `CHANGES REQUESTED` (есть critical/high). Без вердикта ревью не закончено.

## Формат ответа

```
## Ревью: <ветка/PR> против <base>  (±N строк, M файлов)

Вердикт: CHANGES REQUESTED | APPROVE с правками | APPROVE
Итог: 1 critical, 2 high, 1 medium, 3 nit

### Critical
[path/to/file.py:42] critical — <что ломается и при каком входе>
Исправление:
<блок кода: было → стало>

### High
[path/to/other.py:88] high — <описание>
Исправление:
<блок кода>

### Medium / Nit
[file.py:10] nit — <короткая заметка, фикс опционален>
```

Жёсткое правило строки находки: **`[файл:строка] severity — описание`**, и СРАЗУ под ней блок `Исправление:` с кодом (для nit допустим однострочный совет без блока).

## Worked example

Дифф нового эндпоинта:
```python
@app.get("/files/{name}")
async def get_file(name: str, user=Depends(auth)):
    path = "/data/" + name
    sql = f"SELECT * FROM docs WHERE path = '{path}'"
    row = db.execute(sql).fetchone()          # sync-драйвер в async
    return open(path).read()
```

Ревью:
```
## Ревью: feat/file-endpoint против main  (+6 строк, 1 файл)
Вердикт: CHANGES REQUESTED
Итог: 3 critical, 1 high

[api/files.py:3] critical — path traversal: name="../../etc/passwd" уходит за /data/.
Исправление:
  safe = (Path("/data") / name).resolve()
  if not safe.is_relative_to("/data"): raise HTTPException(403)

[api/files.py:4] critical — SQL injection через f-string (name="' OR '1'='1").
Исправление:
  db.execute("SELECT * FROM docs WHERE path = ?", (str(safe),))

[api/files.py:2] critical — authn без authz (IDOR): любой залогиненный читает чужие файлы.
Исправление: добавить WHERE owner_id = :user.id и проверку владения safe.

[api/files.py:5] high — sync db.execute + blocking open() в async-хендлере блокируют event loop.
Исправление: await async-драйвер; await anyio.to_thread.run_sync(safe.read_text).
```

## Анти-паттерны

| Анти-паттерн | Почему плохо | Вместо этого |
|--------------|--------------|--------------|
| **Rubber-stamp LGTM** | «выглядит ок» без чтения = подпись под чужим багом | прочитай дифф + файлы, вынеси явный вердикт |
| **Бикешеддинг стиля** | спор о кавычках/имени, пока SQL-инъекция рядом не замечена | сначала critical/high; nit — в конце и помечен `nit:` |
| **Ревью без diff** | критикуешь «вообще», не зная, что изменилось → шум и ложные срабатывания | стартуй с `git diff $BASE...HEAD` |
| **Замечание без фикса** | «тут плохо» без альтернативы = работа спихнута на автора | каждая находка ≥medium несёт блок `Исправление:` |
| **Всё critical** | если всё горит — приоритета нет, автор игнорит весь ревью | строгая таксономия; critical только с эксплойтом/входом |
| **Призрачные требования** | требуешь то, чего нет в стандартах проекта (вкусовщина как блокер) | блокировать можно только реальным вредом, не предпочтением |

## Границы / Red-flags

- **Дифф не виден / нет базы** → не выдумывай изменения. Запроси ветку или `git diff` прежде чем ревьюить.
- **Сгенерированные/вендоренные файлы** (`*.min.js`, `lock`-файлы, миграции-автоген) — не ревьюй построчно, отметь и пропусти.
- **>1000 строк диффа** → попроси разбить PR; на большом дифе внимание падает, critical теряются. Дай ревью верхнего уровня + предложи split.
- **Доменная логика без контекста** (биллинг, крипто, медицина) → отметь риск, но не утверждай корректность формулы, которую не можешь проверить. Скажи «нужен ревью доменного эксперта».
- **Перфо-claim без бенчмарка** → не пиши «медленно» без оценки сложности или замера; иначе это nit, а не high.
- Не уверен, баг или нет, и контрпример не строится → понизь до nit с пометкой «проверить» или честно скажи **«не знаю, нужен прогон тестов»**. Лучше пропустить сомнительное, чем утопить реальные critical в шуме.
