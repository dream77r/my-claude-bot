# Skill: Трекинг задач команды

## Принцип

**Одна задача = одна запись с устойчивым `id`, явным `owner` и абсолютным дедлайном.**
Файл `wiki/concepts/tasks.md` — единственный источник правды о состоянии работы.
Чат — это поток событий; задача — это материализованная запись. Статус меняется
только через разрешённый переход машины состояний, и только Edit'ом в этом же turn'е.

> Задача ≠ обещание. Обещание (`promises.md`) — добровольное обязательство к моменту;
> задача (`tasks.md`) — единица работы с владельцем и жизненным циклом. Одна задача
> может породить несколько обещаний, но живёт независимо.

## Когда активировать

- **Создание:** «нужно сделать X», «надо прикрутить X», «задача: X», «кто возьмёт X», «давайте сделаем X».
- **Смена статуса:** «взял X», «в работе», «застрял на X», «блокер: Y», «сделал X», «готово».
- **Переназначение:** «передай X Васе», «это теперь на Маше», «сними с меня X».
- **Запрос статуса:** «что по задачам», «мои задачи», «что у @user», «что просрочено», «что в блоке».
- **Недельный rollup:** «итоги недели», «rollup», «что закрыли» — по запросу или раз в неделю (пятница).

## Модель данных — схема записи `tasks.md`

Файл сгруппирован по секциям `## Активные` и `## Закрытые` (done/cancelled уходят вниз).
Одна задача = один блок. Канонический формат записи:

```
- [T-042] **Прикрутить экспорт CSV в кокпит** — owner: @maria — P1 — статус: in_progress
      due: 2026-06-19 — обновлено: 2026-06-15T14:30 — источник: msg#8131
      блокеры: T-039 (ждём схему БД)
```

| Поле | Тип / значения | Обязательно | Правило |
|------|----------------|-------------|---------|
| `id` | `T-NNN`, монотонный | да | `max(существующих)+1`; не переиспользуй id отменённых |
| заголовок | 1 строка, ≤80 симв. | да | глагол + объект («Прикрутить экспорт»), не «экспорт» |
| `owner` | `@tg_username` | **да** | нет owner'а → **спроси**, не записывай безымянной |
| приоритет | `P0`\|`P1`\|`P2`\|`P3` | да | дефолт `P2`, если не указан |
| статус | см. машину состояний | да | только из разрешённого перехода |
| `due` | `YYYY-MM-DD` (абсолютная) | для P0–P2 | **всегда абсолютная**; относительную конвертируй (см. ниже) |
| `обновлено` | `YYYY-MM-DDTHH:MM` | да | время последнего Edit'а этой записи |
| `источник` | `msg#id` или цитата | да | привязка к событию чата |
| `блокеры` | список `id` или текст | нет | строка `блокеры:`; пусто → строку опусти |

**Приоритеты (фиксированная семантика):**

| P | Смысл | Реакция |
|---|-------|---------|
| `P0` | прод лежит / блокирует всю команду | бросай текущее, эскалируй владельцу немедленно |
| `P1` | важно, есть дедлайн на этой неделе | в работу в первую очередь |
| `P2` | нормальная задача (дефолт) | плановая очередь |
| `P3` | nice-to-have / бэклог | без дедлайна допустимо |

## Машина состояний

```
              ┌──────────────────────────────────────────┐
              ▼                                          │
  todo ──▶ in_progress ──▶ done                          │
   │           │   ▲                                     │
   │           ▼   │                                     │
   │        blocked ┘  (разблокировали → in_progress)    │
   │                                                     │
   └──▶ cancelled ◀────────── (из любого статуса) ───────┘
```

**Таблица разрешённых переходов** (всё остальное — запрещено, спроси уточнение):

| Из \ В | todo | in_progress | blocked | done | cancelled |
|--------|:----:|:-----------:|:-------:|:----:|:---------:|
| **todo** | — | ✅ взял | ✅ блокер сразу | ❌ | ✅ |
| **in_progress** | ✅ вернул | — | ✅ застрял | ✅ сделал | ✅ |
| **blocked** | ❌ | ✅ разблок. | — | ✅ обошёл | ✅ |
| **done** | ❌ | ✅ reopen | ❌ | — | ❌ |
| **cancelled** | ✅ воскресил | ❌ | ❌ | ❌ | — |

Инварианты: `blocked` обязан иметь непустую строку `блокеры:`; `done`/`cancelled`
получают строку `└ закрыто: ISO — <причина/цитата>` и переезжают в `## Закрытые`.

## Операции — протоколы

Каждая операция: **Read `tasks.md` целиком → действие → Edit → подтверждение в чат.**
Никогда не подтверждай устно без Edit'а в том же turn'е (это источник дрейфа статуса).

### 1. Создать
1. Read файл, вычисли следующий `id`.
2. Проверь дубль: нет ли уже активной записи с тем же смыслом → если есть, не плоди вторую, уточни.
3. **owner не указан → спроси «кто берёт?»** и не записывай, пока не ответят (либо явное «без владельца, в бэклог» → owner: `@unassigned`, статус `todo`, P3).
4. **дедлайн относительный → конвертируй в абсолютный** (см. конвенции) до записи.
5. Edit: добавь блок в `## Активные`, статус `todo`.

### 2. Обновить статус
1. Read, найди запись по `id` или семантике. 0 кандидатов → спроси какую; 2+ → перечисли, спроси.
2. Проверь переход по таблице. Запрещённый → объясни и спроси (напр. done→todo нельзя, нужен reopen→in_progress).
3. Edit: смени `статус:`, обнови `обновлено:`. Для `blocked` добавь/обнови `блокеры:`. Для `done`/`cancelled` добавь `└ закрыто:` и перенеси в `## Закрытые`.

### 3. Переназначить
1. Read, найди запись. Edit: смени `owner:`, обнови `обновлено:`, добавь `└ переназначено: ISO — @old → @new`.
2. Статус **не** меняется (переназначение ≠ прогресс). Уведоми нового owner'а явным пингом в ответе.

### 4. Закрыть
1. Применяй переход `*→done` (выполнено) или `*→cancelled` (не нужно/дубль).
2. Edit: статус, `└ закрыто: ISO — <короткая цитата>`, перенос в `## Закрытые`.
3. Если у задачи висят открытые блокеры или она сама блокирует другие — отметь это в ответе.

### 5. Запрос статуса
1. Read. Отфильтруй: `@user` / приоритет / просрочено (`due < сегодня` и не done/cancelled) / `blocked`.
2. Ответь компактным списком; детали по запросу. Чужие задачи показывай (внутрикомандная прозрачность), приватные детали — нет.

### 6. Недельный rollup (пятница / по запросу)
1. Read весь файл. Посчитай: закрыто за неделю (`└ закрыто` ≥ понедельник этой недели), создано, в работе, в блоке, **просрочено** (`due < сегодня`, активна).
2. Вынеси красные флаги: P0/P1 просроченные, задачи без движения >7 дней (`обновлено` старое), осиротевшие (`@unassigned`).
3. Edit-гигиена: блок-цепочки, дубли — пометь, не молчи.

## Конвенции

- **Дедлайны всегда абсолютные.** «завтра/к пятнице/через неделю» → конвертируй в `YYYY-MM-DD`
  относительно `сегодня` (текущая дата известна из контекста) **до** записи и **повтори
  абсолютную дату в подтверждении** («до 2026-06-19 (пт)»), чтобы автор подтвердил. Считай
  день недели целевой даты явно — «к пятнице» обязан лечь на пятницу, а не на соседний день.
- **owner обязателен.** Нет владельца → спроси. Молчаливый `@unassigned` только по явному «в бэклог».
- **Одна задача = одна запись.** Перед созданием ищи существующую по смыслу; обновляй её, не клонируй.
- **id неизменен и не переиспользуется.** Отменённую `T-017` не «воскрешают» под `T-031`.
- **Каждый Edit обновляет `обновлено:`** — это топливо для rollup'а «без движения >7 дней».

## Формат ответа (per operation)

```
Создал:        🆕 T-042 «Экспорт CSV» → @maria — P1 — до 2026-06-19
Обновил:       🔄 T-042 in_progress → blocked (блокер: T-039 схема БД)
Переназначил:  ↪️ T-042 @maria → @ivan (статус без изменений)
Закрыл:        ✅ T-042 done — «смержил PR #87»
Запрос:        📋 Активные @maria: T-042 P1 in_progress (до 19.06), T-051 P2 todo (до 24.06)
Rollup:        📊 Неделя: закрыто 7 · в работе 4 · в блоке 2 · ⚠️ просрочено 1 (T-039 P1)
```

Запрещённый переход / нет owner'а / неоднозначность → **вопрос**, не действие.

## Worked example

Чат: «надо прикрутить экспорт в CSV в кокпит, кровь из носу к пятнице» (сегодня 2026-06-15, пн).

1. owner не назван → «Кто берёт экспорт CSV?» → «я, Маша (@maria)».
2. «к пятнице» → конвертирую: ближайшая пятница от пн 15.06 = `2026-06-19`. «кровь из носу» + дедлайн на неделе → `P1`.
3. Read `tasks.md`, max id = `T-041` → новый `T-042`. Дублей нет.
4. Edit, добавляю в `## Активные`:
```
- [T-042] **Прикрутить экспорт CSV в кокпит** — owner: @maria — P1 — статус: todo
      due: 2026-06-19 — обновлено: 2026-06-15T14:30 — источник: msg#8131
```
5. Ответ: `🆕 T-042 «Экспорт CSV в кокпит» → @maria — P1 — до 2026-06-19 (пт)`.

Позже @maria: «застряла, жду схему БД от Ивана» (ср 17.06). → переход `todo→blocked` (через in_progress допустимо одним Edit'ом, фиксирую факт блокера). Edit:
```
- [T-042] ... — статус: blocked
      due: 2026-06-19 — обновлено: 2026-06-17T11:05 — источник: msg#8204
      блокеры: ждём схему БД от @ivan (см. T-039)
```
Ответ: `🔄 T-042 → blocked (ждём схему БД, @ivan / T-039)`.

## Анти-паттерны

| Анти-паттерн | Чем плохо | Правильно |
|--------------|-----------|-----------|
| Осиротевшая задача без owner | никто не делает, висит вечно | спроси «кто берёт?» до записи |
| Тихий дрейф статуса | устно «закрыл», файл с `[todo]` | статус меняется **только** Edit'ом в том же turn'е |
| Дубль одной задачи | две записи, рассинхрон статусов | Read+поиск по смыслу до create; обновляй существующую |
| «завтра/к пятнице» в `due` | неоднозначно через 2 дня | конвертируй в `YYYY-MM-DD`, сверь день недели, повтори в подтверждении |
| Запрещённый переход (done→todo) | ломает аудит-историю | reopen → `done→in_progress`, объясни |
| `blocked` без строки `блокеры:` | непонятно, чего ждём | блокер обязателен, иначе это `in_progress` |
| Переиспользование id | путает историю и блок-ссылки | id монотонный, навсегда |
| Переназначение сбрасывает статус | теряется прогресс | owner меняется, статус — нет |

## Границы / Red-flags

- **Нет owner'а и непонятно, кто берёт** → спроси, не записывай безымянную задачу.
- **Неоднозначный матч (2+ кандидата)** на статус/закрытие → перечисли, спроси «какую?», не угадывай.
- **Запрошен запрещённый переход** → не выполняй, объясни допустимый путь.
- **Edit не удался** → скажи прямо «не смог обновить tasks.md, причина <X>», не подтверждай устно.
- **P0 (прод лежит / блок всей команды)** → эскалируй владельцу немедленно, не жди rollup'а.
- **Не выдумывай дедлайн.** Для P3 допустим `due` отсутствует; для P0–P2 нет даты → спроси.
- **Сомнения в дате** («к пятнице», а сегодня уже четверг?) → озвучь, какую именно дату ставишь, и дай автору поправить.
- **Это обещание, не задача?** Личное обязательство к моменту без владельца-исполнителя — отправь в `promise-tracking`, не плоди запись в `tasks.md`.
