# Skill: База знаний команды

**Принцип:** ни одно решение и ни один факт не живёт только в чате — он попадает в `wiki/` со ссылкой на источник, иначе его не существует. Поиск всегда возвращает ответ + источник; запись всегда обновляет `index.md`.

## Когда активировать

| Сигнал | Режим |
|--------|-------|
| «запомни / запиши / сохрани X» | **Захват** факта → wiki-страница |
| «мы решили / договорились / наше решение» | **Захват** решения → ADR-lite запись |
| «что мы решили по…», «где у нас…», «кто отвечает за…», «найди в базе» | **Извлечение** (grep-лестница) |
| Решение принято в группе, но никто не просил записать | **Захват** проактивно (тихо, 1 строкой подтверди) |

## Структура wiki

```
wiki/
├── index.md                  # КАТАЛОГ — обновляется при КАЖДОМ создании страницы
├── concepts/                 # задачи, проекты, процессы, договорённости
│   ├── decisions.md          # ADR-lite журнал ВСЕХ решений (append-only)
│   └── <slug>.md             # одна тема = одна страница
├── entities/                 # люди, команды, роли, контрагенты («кто отвечает»)
│   └── <slug>.md
└── synthesis/                # дайджесты, сводки (генерируются Dream/cron, руками не трогай)
```

**slug** — kebab-case, латиница/транслит, без пробелов. ru→lat транслит + `[^a-z0-9]→-`, схлопни повторы дефиса:

| Источник | slug |
|----------|------|
| «Переписать биллинг» | `billing-rewrite` (смысловой, не дословный транслит) |
| «Иван Петров» | `ivan-petrov` |
| «Релизный процесс» | `release-process` |
| «ООО Ромашка» | `romashka-ooo` |

## Что считается РЕШЕНИЕМ (а что просто фактом)

Решение (→ ADR-lite) — есть **выбор из альтернатив** + **обязательность**. Маркеры: «решили», «договорились», «остановились на», «делаем X вместо Y», «утвердили», «больше не делаем Z».
Факт (→ обычная страница) — наблюдение/реквизит/статус без выбора: «дедлайн 1 июля», «у Маши доступ к проду», «API живёт на api.example.com». При сомнении: есть отвергнутая альтернатива? → решение. Нет → факт.

## Протокол ЗАХВАТА

### A. Обычный факт → wiki-страница
1. **Дедуп:** `grep -rilE "<термин1>|<термин2>" wiki/` — есть страница по теме? → **Edit** её, не плоди новую.
2. Нет → **Write** `wiki/concepts/<slug>.md` (или `entities/` для людей/ролей).
3. Линкуй связанные сущности через `[[wiki-slug]]` (напр. `[[ivan-petrov]]`).
4. **ОБНОВИ `index.md`** — добавь строку в нужную секцию. Без этого шага запись считается незавершённой (страница не видна каталогу).

### B. РЕШЕНИЕ → ADR-lite (обязательный формат)
Любое «мы решили / договорились / наше решение» = **append** в `wiki/concepts/decisions.md` блоком:

```markdown
## ADR-NNN — <короткий заголовок решения>
- **Контекст:** <почему встал вопрос, какая проблема/триггер>
- **Решение:** <что именно постановили, в одну фразу>
- **Обоснование:** <почему так, какие альтернативы отвергли>
- **Дата:** YYYY-MM-DD
- **Кто принял:** <имена/роли участников>
- **Затронутые:** [[slug-A]], [[slug-B]] <страницы/люди/проекты>
```

`NNN` = `(grep -c '^## ADR-' wiki/concepts/decisions.md) + 1`, дополни нулями до 3 знаков (6 записей → ADR-007). Журнал append-only и без пропусков, поэтому счётчик = надёжный следующий номер. Дата обязательна — решение без даты невалидно. Если контекст/участники не названы — **спроси одной фразой**, не выдумывай.

## Протокол ИЗВЛЕЧЕНИЯ (grep-лестница)

Поднимайся по ступеням, **останавливайся как только нашёл**:

| # | Шаг | Команда |
|---|-----|---------|
| 1 | Точный термин | `grep -rin "<термин>" wiki/` |
| 2 | Синонимы/морфология | `grep -rinE "<стем1>|<стем2>|<англ>" wiki/` |
| 3 | Связанные страницы | по найденным `[[slug]]` → расширь поиск |
| 4 | Решения | `grep -in "<тема>" wiki/concepts/decisions.md` |
| 5 | Каталог | `grep -in "<тема>" wiki/index.md` → точечный **Read** файла |
| 6 | Прочитать | **Read** найденного файла целиком перед ответом |

Не нашёл за 6 ступеней → честно «в базе нет записи по X» + предложи записать.

## Как применять (алгоритм)

```
1. Классифицируй запрос: ЗАХВАТ или ИЗВЛЕЧЕНИЕ?
2. ИЗВЛЕЧЕНИЕ → пройди grep-лестницу 1→6, Read источник, ответь со ссылкой.
3. ЗАХВАТ:
   3a. grep на дубликат → есть? Edit. Нет? Write.
   3b. Это решение (выбор из альтернатив)? → ADR-lite в decisions.md (все 6 полей).
   3c. Проставь [[wiki-slug]] линки на связанные сущности.
   3d. Обнови index.md (НЕ пропускай).
4. Подтверди в формате ответа.
```

## Формат ответа

**При поиске** — ответ + источник всегда:
```
<краткий ответ по сути>
Источник: wiki/concepts/<slug>.md   (• ADR-007, если решение)
```

**При записи факта:**
```
📝 Записал: wiki/concepts/<slug>.md → index.md обновлён
```

**При записи решения:**
```
📝 ADR-NNN «<заголовок>» → wiki/concepts/decisions.md (дата YYYY-MM-DD)
```

## Worked example

> User: «Договорились биллинг переписываем на новом стеке, старый замораживаем — решали Иван и Маша сегодня».

Классификация: есть выбор (новый стек *вместо* рефакторинга) + обязательность → **решение**.
```bash
grep -rilE "биллинг|billing" wiki/              # → дубля нет
grep -c '^## ADR-' wiki/concepts/decisions.md   # → 6, значит NNN = 6+1 = ADR-007
```
Append в `wiki/concepts/decisions.md`:
```markdown
## ADR-007 — Переписать биллинг на новом стеке
- **Контекст:** старый биллинг тормозит развитие, накопился тех-долг
- **Решение:** пишем заново на новом стеке, легаси замораживаем (только bugfix)
- **Обоснование:** дешевле переписать, чем чинить; альтернативу «рефакторить на месте» отвергли
- **Дата:** 2026-06-16
- **Кто принял:** Иван, Маша
- **Затронутые:** [[billing-rewrite]], [[ivan-petrov]]
```
Обновить `index.md` (секция concepts): `- [[billing-rewrite]] — переписываем биллинг (ADR-007, 2026-06-16)`.
Ответ: `📝 ADR-007 «Переписать биллинг на новом стеке» → wiki/concepts/decisions.md (2026-06-16)`

## Анти-паттерны

| ❌ Ошибка | ✅ Правильно |
|-----------|-------------|
| Создал страницу, не тронул `index.md` | index.md обновляется при КАЖДОМ Write — иначе страница невидима поиску |
| Новая страница вместо обновления существующей | grep-дедуп ПЕРЕД Write; нашёл — Edit |
| Записал факт как ADR (нет альтернатив) | ADR только при выборе из вариантов; иначе обычная страница |
| Решение без даты/контекста | все 6 полей ADR-lite обязательны; нет контекста — спроси |
| Ответил по памяти без grep | сначала grep-лестница, ответ только из найденного |
| Ответ без ссылки на источник | каждый ответ-поиск заканчивается `Источник: …` |
| Дублирующая инфа в двух местах | один факт = одна страница; остальное линкует через `[[slug]]` |
| Записал «как-нибудь», потерял кто сказал | фиксируй источник/автора решения |

## Границы / Red-flags

- **Конфликт записей** (новый факт противоречит старому) → не перезаписывай молча; покажи оба, спроси что верно, и пометь устаревшее.
- **Чувствительные данные** (пароли, токены, перс. данные) → НЕ пиши в wiki, скажи об этом.
- **«Решили», но участники/дата неясны** → один уточняющий вопрос, не выдумывай поля ADR.
- Не нашёл в базе → честно «нет записи», не галлюцинируй ответ.
- НЕ удаляй и не переписывай чужие ADR-записи — журнал append-only; изменение оформляй новым ADR со ссылкой на отменяемый («заменяет ADR-NNN»).
- `synthesis/` генерируется Dream/cron — руками не редактируй, перетрут.
- Файлы только внутри `agents/team/memory/wiki/`; в `raw/` и чужие memory не лезь.
