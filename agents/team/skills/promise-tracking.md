# Skill: Promise Tracking

## Принцип

Обещание — это любое добровольное обязательство участника чата сделать что-то к какому-то моменту. Скилл отслеживает жизненный цикл обещания: **взято → в работе → закрыто** (или **просрочено → перенесено**).

## Парсинг обещания

Паттерны, которые считаются обещанием:

- «Я возьму X»
- «Я сделаю X к Y»
- «Обещаю X до Y»
- «Я беру это на себя»
- «Я делаю X сегодня/завтра/до пятницы»
- Ответ на утренний стендап с планом на день

**Что извлекать:**

| Поле | Источник |
|------|---------|
| `who` | tg username автора сообщения |
| `what` | краткое описание задачи (1 предложение) |
| `due` | дедлайн в ISO (если сказано «к Y» — распарсить, иначе конец дня из `settings.json` → `daily_sync.day_end_time`) |
| `source_message_id` | id исходного сообщения (если доступно в контексте) |
| `created_at` | ISO timestamp сейчас |

## Запись обещания

1. Прочитай `wiki/concepts/promises.md`.
2. Найди секцию `## YYYY-MM-DD` для сегодня. Если нет — создай.
3. Добавь новый пункт в формате, описанном в промисах:
   ```
   - [ ] **@username** — описание задачи — дедлайн: YYYY-MM-DD HH:MM — добавлено: ISO
         └ источник: message_id или краткая цитата
   ```
4. Коротко подтверди в чат: «📝 Записал: @user — задача — до HH:MM».

## Отметка выполнения

Паттерны:
- «Сделал X» / «Готово» / «Закрыл X» / «Done» / «Сдал» / «Отгрузил» / «Релизнул» / «всё закрыто»
- Явное упоминание задачи из `promises.md`

**Жёсткий протокол (в этом порядке, не сокращай шаги):**

1. **Read `promises.md` целиком.** Не доверяй контексту в памяти LLM — файл мог
   измениться между turn'ами.
2. **Собери ВСЕ открытые `[ ]` от этого `@user`** по всем секциям файла, у
   которых нет строки `└ закрыто:`. Не ограничивайся «сегодняшней» секцией —
   задача может висеть с прошлой недели.
3. **Сматчь:** выбери ту запись, которая семантически совпадает с
   сообщением user'а. Если кандидатов:
   - **0** → ответь «не вижу открытой задачи у тебя, может я её не записывал?
     уточни какую закрываешь» — и НЕ редактируй файл.
   - **1** → переходи к шагу 4.
   - **2+** → ответь «вижу несколько открытых: <список>. Какую именно?» — и
     НЕ редактируй файл. (Исключение: «все/всё закрыто» от user'а — закрываем
     ВСЕ его открытые `[ ]` одним Edit'ом, каждой ставим
     `└ закрыто: ISO — массовое закрытие по слову "все"».)
4. **Edit `promises.md`:** замени найденную `[ ]` на `[x]` и добавь строку
   `└ закрыто: ISO timestamp — <короткая цитата>`. Если у задачи есть
   `[ ]`-дубликаты с прошлых дней (zombie-клоны от старой версии
   evening_digest) — закрой их все одним Edit'ом, каждой с пометкой
   `└ закрыто: ISO — дедуп при закрытии`.
5. **Только после успешного Edit** напиши в чат: `✅ Закрыл: <задача> (запись
   от <дата исходной секции>)`.

**Никогда не пиши «✅ закрыл» в чат, не сделав Edit в этом же turn'е.**
Это главный источник «памяти барахлит» — LLM подтверждает устно, файл
остаётся со старым `[ ]`, вечерний дайджест видит задачу открытой, утром
рапортует «просрочено». Если по какой-то причине Edit не удался — скажи
user'у напрямую: «не смог обновить promises.md, причина <X>», а не ври
что закрыл.

## Перенос невыполненного

Вызывается из `daily-sync` вечером.

**Принцип: НЕ клонировать.** Старая версия этого шаблона создавала каждый
вечер дубликат `[ ]` в секции `## завтра`. За 22 дня одна задача накапливала
22 открытые записи (zombie-клоны), и закрытие одной не закрывало остальные.

Новый алгоритм:

1. Для каждого `[ ]` в любой секции файла, где `due < now()` и нет `закрыто:`:
   - Если у задачи ещё нет строки `└ перенесено на ...` за сегодня — добавь её:
     `└ перенесено на YYYY-MM-DD — причина: не отмечено как выполненное вечером`.
   - **НЕ создавай дубликат в секции `## завтра` и нигде ещё.** Исходная `[ ]`
     остаётся в своей секции — она и есть открытое обещание. Утренний стендап
     найдёт её сканированием всех открытых `[ ]`.
2. Если ты видишь существующие zombie-клоны (несколько `[ ]` от одного `@user`
   с близким описанием) — закрой все кроме самой ранней с пометкой
   `└ закрыто: ISO — дедуп вечером, исходная запись от <дата>`. Это разовая
   гигиена после миграции с старого формата.

## Запросы статуса

Паттерны:
- «Что у меня?» / «Что я обещал?» / «Мои задачи»
- «Что у @user?» (если `settings.json` → `privacy.hide_from_others: false`)
- «Что просрочено?» / «Что вчера не закрыли?»

Ответ: короткий список с датами и статусами. Детали — если спросят.

## Ограничения

- **Не записывай одно и то же дважды.** Перед добавлением проверь, нет ли уже такого обещания от этого участника сегодня.
- **Не придумывай дедлайны.** Если не сказано — ставь конец рабочего дня (`day_end_time`).
- **Уважай приватность.** По умолчанию участник видит свои обещания и общий план команды. Чужие детали — только если не запрещено в `settings.json`.
- **Обещание — это не задача.** Задача живёт в `wiki/concepts/tasks.md`, обещание — в `promises.md`. Одна задача может породить несколько обещаний.
