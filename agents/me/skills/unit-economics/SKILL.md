# Skill: Unit Economics — юнит-экономика точки и подписки

**Принцип:** считай скриптом, а не в уме — LLM ошибается в длинных арифметических цепочках. Каждая метрика выводится из `scripts/calc.py`, числа в ответе должны совпадать с его выводом. GIGO: качество вывода = качество входных допущений, поэтому допущения всегда явные.

## Когда активировать

- «Окупится ли точка / за сколько месяцев», «сколько чеков в день до нуля», «выгодно ли открывать на этой аренде».
- «Посчитай LTV / CAC / LTV:CAC / payback», «сходится ли юнит-экономика подписки BrewOS».
- «Какая маржинальность / contribution», «где порог безубыточности».
- «Разбери когорту / retention / отток».
- Любой расчёт «инвестировал X — вернётся когда / сколько ROI».
- НЕ активировать на полном P&L-отчёте за период — это `pl-analysis`. Юнит-экономика — про экономику ОДНОЙ единицы (точка, клиент, подписка), а не про сводный отчёт.

## Метрики и формулы

Всё в `calc.py`. Доли (`gross_margin`, `churn`, `cogs_pct`) задаются как 0..1.

### Общие (подписка / клиент)

| Метрика | Формула | Целевой ориентир |
|---|---|---|
| **CAC** (blended) | `весь S&M / все новые клиенты` | контекст |
| **CAC** (paid) | `платный S&M / привлечённые платно` | paid >= blended всегда |
| **LTV** (gross-adj) | `ARPU × gross_margin% × (1 / churn)` | — |
| **LTV** (contribution) | `contribution_за_период / churn` | точнее при переменных не-COGS |
| **Срок жизни** | `1 / churn` (периодов) | — |
| **LTV:CAC** | `LTV / CAC` | **>= 3:1** (коридор 3–5) |
| **CAC payback** | `CAC / (ARPU_мес × gross_margin%)` | SaaS **< 12 мес** |
| **Contribution margin** | `цена − переменные затраты` (абс. и %) | — |
| **Cohort retention[t]** | `active[t] / active[0]` | — |
| **Period churn[t]** | `1 − active[t]/active[t−1]` | — |

**ВАЖНО про LTV:** всегда умножай на `gross_margin%`. LTV по выручке (без маржи) завышает в 1/gross_margin раз и ломает решения о CAC.

### Для ТОЧКИ (кофейня / ретейл F&B)

| Метрика | Формула |
|---|---|
| **Выручка/мес** | `AOV × tx_per_day × days` |
| **AOV (средний чек)** | `выручка / число чеков` |
| **COGS** | `выручка × cogs_pct` (food cost) |
| **Contribution** | `выручка − COGS − переменный труд` |
| **Постоянные** | `ФОТ(пост.) + аренда + прочие фикс` |
| **Операционная прибыль** | `contribution − постоянные` |
| **Operating margin** | `операц. прибыль / выручка` |
| **Break-even (выручка)** | `постоянные / contribution_margin%` |
| **Break-even (чеков/день)** | `break-even выручка / (AOV × days)` |
| **Окупаемость точки** | `инвестиции / операц. прибыль_мес` (мес) |
| **ROIC год.** | `операц. прибыль_мес × 12 / инвестиции` |

### SaaS-довески

| Метрика | Формула | Норма |
|---|---|---|
| **Magic number** | `net new ARR (annualized) / S&M пред. квартала` | > 0.75 — лей в рост |
| **Rule of 40** | `рост% + маржа%` | **>= 40** |

## Бенчмарки / пороги (ориентиры, не догма)

| Показатель | Зелёная зона | Красный флаг |
|---|---|---|
| LTV:CAC | 3–5 | < 1 (убыток на клиенте); > 5 = недоинвест в рост |
| CAC payback (SaaS) | < 12 мес | > 18 мес (кассовый разрыв) |
| Окупаемость кофейни | **12–24 мес** | > 24 мес или ∞ |
| Gross margin кофейни | **65–75%** (COGS 25–35%) | COGS > 35% |
| Labor (ФОТ) | **25–30%** выручки | > 30% (переукомплект/низкий трафик) |
| Аренда | 10–15% выручки | > 20% |
| Операционная маржа точки | 10–20% | <= 0 |
| Monthly churn (подписка B2C) | 3–7% | > 10% |

## Метод (Как применять)

1. **Собери входные допущения.** Спроси/вытащи минимум: для точки — AOV, чеков/день, COGS%, ФОТ, аренда, прочие фикс, инвестиции; для подписки — ARPU(мес), gross margin, churn(мес), S&M-расход, новые клиенты. Чего нет — помечай как ДОПУЩЕНИЕ и бери осторожную оценку.
2. **Посчитай скриптом.** Из памяти агента (cwd = `agents/me/memory/`):
   ```bash
   # точка
   python3 ../skills/unit-economics/scripts/calc.py store \
     --aov 350 --tx-per-day 150 --cogs-pct 0.30 \
     --labor 470000 --rent 280000 --other-fixed 180000 --investment 5500000
   # подписка
   python3 ../skills/unit-economics/scripts/calc.py saas \
     --arpu 1200 --gross-margin 0.80 --churn 0.03 \
     --sm-spend 900000 --new-customers 300 --net-new-arr 3600000
   # когорта
   python3 ../skills/unit-economics/scripts/calc.py cohort --sizes 1000 820 700 620 560 510
   # дымовой тест (проверить, что скрипт жив и считает верно)
   python3 ../skills/unit-economics/scripts/calc.py --self-test
   ```
   Бери числа ИЗ ВЫВОДА скрипта, не пересчитывай руками. `--json` (после подкоманды) — если нужен машинный формат.
3. **Интерпретируй по бенчмаркам.** Каждую метрику — против таблицы порогов. Где зелёная зона, где красный флаг.
4. **Найди рычаги.** Какие 1–2 входа двигают итог сильнее всего (обычно: AOV, трафик, COGS%, ФОТ% — для точки; churn и CAC — для подписки). Прогони скрипт ещё раз с изменённым входом, покажи дельту.
5. **Рекомендации.** 3–5 конкретных действий с числами («поднять AOV с 350 до 400 → payback с 32 до ~17 мес»). Для глубоких определений, источников входов и sensitivity-разбора — `references/playbook.md`.

## Worked example — кофейня Lintu (флагман)

Вход: AOV 350 ₽, 150 чеков/день, COGS 30%, ФОТ 470к, аренда 280к, прочие фикс 180к, инвестиции 5.5 млн.
Команда: `calc.py store --aov 350 --tx-per-day 150 --cogs-pct 0.30 --labor 470000 --rent 280000 --other-fixed 180000 --investment 5500000`

| Метрика | Значение | vs бенчмарк |
|---|---|---|
| Выручка/мес | 1 575 000 ₽ | — |
| COGS | 472 500 ₽ (30%) | 🟢 норма 25–35% |
| Labor | 470 000 ₽ (29.8%) | 🟡 у верхней границы 25–30% |
| Contribution | 1 102 500 ₽ (70%) | 🟢 |
| Операц. прибыль | 172 500 ₽ (11.0%) | 🟢 в норме 10–20% |
| Break-even | 127 чеков/день | 🟡 запас всего 15% (150 vs 127) |
| Окупаемость | 31.9 мес | 🔴 > 24 мес, долго |
| ROIC | 37.6%/год | — |

**Чтение:** точка прибыльна (172.5к/мес, маржа 11%), но запас прочности тонкий — упадёт трафик ниже 127 чеков/день и уйдёт в минус. Окупаемость 32 мес — выше нормы 12–24; инвестиции 5.5 млн великоваты для этого объёма выручки.

**Топ-3 рычага** (каждый прогнан через скрипт):
1. AOV 350 → 400 ₽ (апсейл, выпечка): выручка 1.8 млн, операц. прибыль 330к/мес, окупаемость → 16.7 мес. Сильнейший рычаг.
2. Трафик 150 → 180 чеков/день: операц. прибыль 393к, окупаемость → 14.0 мес.
3. ФОТ 470к → 410к (29.8% → 26%): операц. прибыль 232.5к, окупаемость → 23.7 мес. Слабее, рискует сервисом.

SaaS-довесок (подписка BrewOS, ARPU 1200, GM 80%, churn 3%, S&M 900к / 300 клиентов): CAC 3 000 ₽, LTV 32 000 ₽, **LTV:CAC 10.67**, payback **3.1 мес**, magic number 4.0 → юнит-экономика подписки сходится с большим запасом; узкое место не экономика, а объём привлечения.

## Анти-паттерны

| Грабли | Почему плохо | Правильно |
|---|---|---|
| LTV без gross margin | завышает в 1/GM раз, CAC кажется «отбиваемым» | всегда `× gross_margin%` |
| Blended CAC вместо paid | прячет дорогой платный канал за органикой | разнеси paid отдельно |
| Считать арифметику в уме | LLM ошибается в цепочках | всегда `calc.py` |
| Окупаемость от выручки, не от прибыли | «окупится за 3 мес» — фантазия | делить инвестиции на операц. прибыль |
| Игнорировать переменный труд в contribution | завышает contribution точки | `--variable-labor-pct` |
| Survivorship в когортах | берёшь только выживших — churn занижен | фиксируй базу периода 0 |
| Допущения молча | нельзя проверить, спор бесполезен | перечисли явно в ответе |

## Границы / Red-flags

- Это **не аудит и не P&L**. Прикидка юнит-экономики на допущениях, а не сверка с бухгалтерией. Для отчёта за период — `pl-analysis`.
- **Допущения должны быть явными.** Если ключевого входа нет (реальный COGS%, churn, S&M) — не выдумывай точное число: пометь как оценку и покажи диапазон.
- **GIGO.** Мусор на входе → мусор на выходе. Сначала проверь, что входы реалистичны (COGS 5%? churn 0%? — почти всегда ошибка ввода).
- **Не путай месяц и год** в ARPU/churn — формула payback требует МЕСЯЧНЫЙ ARPU.
- **LTV:CAC > 8** часто означает не «отлично», а недоинвестирование в рост ИЛИ ошибку (заниженный CAC, завышенный LTV) — перепроверь вход.
- Стоп и эскалация к человеку: решения о закрытии/открытии точки, привлечении инвестиций, смене модели — скрипт даёт цифру, решение за основателем. Скажи «не знаю», если данных для метрики нет, вместо правдоподобного числа.
