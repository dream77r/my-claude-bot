# Skill: task-status — фиксация смены статуса

## Зачем

User говорит «Stage 3 отгружен», ты отвечаешь «понял, закрыто»,
но `roadmap.md` остаётся со старым статусом. На следующее утро
`morning_briefing` читает stale roadmap и снова рапортует «Stage 3 просрочен».
User получает галлюцинацию и говорит «ты что, забыл?».

Этот скилл закрывает петлю: **устное подтверждение → правка файла**.

## Когда срабатывает

Любое сообщение пользователя со словами-маркерами завершения:
*сделал/готово/закрыл/отгрузил/выкатил/done/shipped/релизнули/смержили/
заморозили/отменили/перенесли* — особенно рядом с именем этапа,
задачи, фичи или модуля.

Также: если user отвечает «да/верно/именно» на твою прямую гипотезу
«я правильно понимаю, что задача X закрыта?».

## Алгоритм

1. **Определи объект** — что именно сменило статус. Спроси one-shot
   уточняющий вопрос, если не уверен («какой именно Stage 3 — A2A или
   что-то новое?»). Не гадай.

2. **Найди источник истины** — обычно это `./wiki/concepts/roadmap.md`,
   но может быть и `./wiki/concepts/<feature>.md`. Используй Grep, чтобы
   найти все упоминания объекта в wiki.

3. **Сверь с git history** (для технических задач) — `git log --oneline
   --grep="<keyword>"` или поиск по диапазону дат. Если коммита нет —
   спроси user'а: «не нашёл коммит, это правка вне репозитория?».

4. **Сделай Edit** — изменения должны быть **в одной правке**:
   - Замени строку статуса на `**Статус: ✅ Закрыто | <ISO дата> | <короткое доказательство>**`
   - Под маркер добавь bullet с коммитом/PR/ссылкой
   - Если есть футер `*Последнее обновление: ...*` — обнови его
   - Не удаляй исторический контекст и не переписывай весь файл

5. **Подтверди в чат одной строкой:**
   `✅ Зафиксировал: <объект> закрыт. Обновил roadmap.md (<file:lineN>).`

6. **Лог в `log.md`** — одну строку:
   `[YYYY-MM-DD HH:MM] task-status: закрыт «<объект>», источник: <коммит/слова user'а>`

## Что НЕ делать

- **Не подтверждай без правки файла.** Если по какой-то причине Edit
  не получился (нет права, не нашёл паттерн) — скажи user'у напрямую:
  «устно понял, но не смог обновить roadmap.md потому что <причина>».
- **Не марши всё подряд закрытым.** Один сигнал = одна задача =
  одна правка. Если user перечислил три закрытия — три правки.
- **Не выдумывай коммиты.** Если git pустой и user не привёл
  доказательств — ставь маркер `🟡 Со слов пользователя, не верифицировано`
  вместо `✅ Закрыто`.

## Связь с другими механизмами

- `morning_briefing` читает `roadmap.md` — если ты обновил статус,
  завтрашний briefing уже не будет паниковать про просрочку.
- `deadline_check` игнорирует строки со статусом `✅`/`Готово`/`Закрыто`
  (см. `agent.yaml::deadline_check.prompt` шаг 4).
- `reality_check` (предутренний триггер) делает обратное направление:
  ловит ситуации, когда коммит уже есть, а roadmap.md не отметил.
